# 作业学习说明：每一步为什么做，每个文件有什么用

## 先理解你交的是什么

这是从随机权重开始训练的小语言模型，不调用聊天 API，也不加载预训练权重。
给模型一段文本，让它预测下一个 token。你的贡献是研究并验证一个改进，
而不是重新发明整个 Transformer。最终分数必须来自老师原样提供的评估器。

## 操作步骤与意义

1. **保留原包，解压到独立目录。** 原 ZIP 是回溯依据；数据、分词器、基线和评分器保留不动，避免改变题目。
2. **创建 Python 3.12 虚拟环境。** `.venv` 隔离依赖，不影响电脑其他 Python 项目。CUDA 版 PyTorch 使用显卡训练；最终仍用 CPU FP32 复现。
3. **检查模型契约。** 不只是看程序能否启动，还检查预测是否偷看未来、概率是否归一化、样本是否独立、窗口之间是否遗留状态，以及是否能反向传播。
4. **跑原始基线。** 获得你这台机器上的质量和时间参照，不直接把老师的约 2.10 当成本机实测结果。
5. **只替换前馈网络。** 原模型为 `Linear -> GELU -> Linear`；新模型为 `SiLU(gate(x)) * value(x) -> Linear`。门控根据输入调节哪些特征通过。
6. **匹配参数量。** 门控网络有三个投影，所以把中间宽度从 512 缩到 344。两种模型总参数量接近，减少“只是参数更多”的混淆。
7. **做同预算比较。** 每个 1200 步实验都处理 `1200*32*256=9,830,400` 个训练目标。种子 17/29 各跑一对，用来观察改进是否稳定。
8. **做消融。** `gated=False` 恢复基线。单元测试验证该分支和原基线在同一随机种子下完全一致。移除机制后的表现就是对照，不必为了改文件名再重复一模一样的训练。
9. **只看验证集选方案。** 训练损失反映训练集拟合；验证 BPB 反映未参与训练文本上的预测表现。保存 `best.pt`，同时保留最终 `checkpoint.pt`。公平固定预算比较使用最终 checkpoint。
10. **单独研究训练时长。** 如果继续训练有帮助，额外训练结果单独列出；不能把更多计算带来的提升都归功于门控结构。
11. **冻结方案。** 把最终权重、配置和源代码哈希记录下来，再运行测试集。哈希是文件内容指纹，便于确认之后评估的是同一模型。
12. **完整测试与资源测量。** 用 FP32、CPU、完整测试集获得 BPB；同机相同线程比较评分耗时，监控评估进程峰值 RAM，计算推理资产未压缩大小。
13. **写报告和打包。** 报告解释方法、控制变量、失败或成功的证据和局限；打包后别人无需重新训练就能评估。
14. **本人复核后提交。** 理解代码，填写自己的学号和公开链接，完成课程网站生成的 GitHub issue。AI 披露必须保留；不能把 AI 起草的内容声称为完全独立完成。

## 关键代码对应的数学含义

- 输入 `ids`：形状 `[B,T]`，每个元素是 0 到 2047 的整数。
- `token(ids)`：查表得到 `[B,T,D]` 的 token 向量。
- `pos(...)`：位置向量；与 token 向量相加，让模型知道顺序。
- `is_causal=True`：第 t 个位置只能读到当前及更早的输入。
- 残差 `x + sublayer(x)`：保留已有信息，叠加新计算，便于梯度传播。
- 前馈层：对每个位置的特征做非线性变换；本作业改进集中在这里。
- 输出头：把特征转换为 2048 个词表项的分数。
- `cross_entropy`：让真实下一个 token 的预测概率更高。
- `loss.backward()`：计算参数如何影响误差；`optimizer.step()` 据此更新权重。
- `log_softmax`：把分数变成归一化自然对数概率，满足评分器接口。
- `BPB = 总负对数概率 / ln(2) / 原始UTF-8字节数`：越低代表预测越好。分母按老师协议计算，不能自行改成 token 数。

## 已完成的结果与读法

四组完整实验均为 1200 步、每步 32 条、每条 256 个目标。下表是验证分数，不是提交分数。

| 随机种子 | 原始 GPT | SwiGLU GPT | 说明 |
|---|---:|---:|---|
| 17 | 2.07289 | 2.01735 | 同样训练目标数，门控模型更好。 |
| 29 | 2.07743 | 2.01662 | 第二个种子也支持相同方向。 |
| 平均 | 2.07516 | 2.01698 | 平均验证 BPB 下降约 2.80%。 |

最终按验证集选中了种子 29 的门控模型，使用第 1200 步权重。
完整 CPU FP32 测试得到 **2.0478319960871167 BPB**，基线种子 17 为 **2.1027022168964282**。
最终测试相对下降约 **2.61%**。这两个测试分数来自不同种子，不能把它们当成同种子因果对照；
方法有效的主要证据来自上表两组同种子验证比较。只有两个种子，也不能声称已经证明普遍统计显著性。

后来发起的 4800 步实验在系统异常重启前没有留下结果，已标记中断，没有伪装成完成实验。
黑屏原因未确定；此后不再启用 GPU 训练。已有四组实验足以完成同预算对照和消融要求。
**现在复现最终成绩只需 CPU 加载现有权重，不必重新训练。**

资源测量第一次只监控到 Windows 虚拟环境启动器，约 4 MiB 的读数不真实。
已修正为同时监控启动器及其 Python 子进程；初次日志保留在 `results/benchmark_launcher_only/`，
不能用它判断内存合规。正式结果以 `results/benchmark/summary.json` 为准。
